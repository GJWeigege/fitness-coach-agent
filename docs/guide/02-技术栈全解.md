## 2. 后端核心依赖

| 包 | 版本约束 | 用途 |
|----|----------|------|
| `fastapi` | ≥0.115 | HTTP API、依赖注入、BackgroundTasks |
| `langgraph` | ≥0.2 | `StateGraph`、条件边、`Send` 并行 |
| `sqlalchemy[asyncio]` | ≥2.0 | 异步 ORM |
| `pgvector` | ≥0.3 | `KnowledgeChunk.embedding` 余弦距离 |
| `pydantic-settings` | ≥2.6 | `Settings` 环境变量 |
| `pypdf` | ≥5 | 知识库 PDF 解析 |
| `pytest` + `pytest-asyncio` | ≥8 / ≥0.24 | 49 个 `test_*.py` |

**未引入**：Celery、Redis、Neo4j、LangChain 全量框架——LangGraph + 自研 `DashScopeClient` 足够轻量。

### 2.1 为何 LangGraph 而非 LangChain AgentExecutor

| 维度 | LangGraph | 传统 AgentExecutor |
|------|-----------|-------------------|
| 状态 | 显式 `CoachState` + reducer | 隐式 message list |
| 并行 | 原生 `Send` fan-out | 需自研 asyncio |
| 路由 | 条件边函数可单测 | 链式 callback 难测 |
| 持久化边界 | 图内 no-op persist，Service 写库 | 易与 DB 耦合 |
| 依赖 | 仅 `langgraph` + `langchain_core.runnables` | 全量 langchain 更重 |

本项目 deliberately 不用 LangChain Tool/agent adapter（ADR-001），仅借用 `RunnableConfig` 传递 configurable。

### 2.2 为何 PostgreSQL + pgvector 而非专用向量库

- 知识库规模 MVP 级（数百 chunk），pgvector HNSW/IVFFlat 足够
- **同一事务**：chat message、retrieval_log、graph_entity_links 与 chunk 查询无跨库一致性问题
- 运维：单 Postgres 备份/迁移，Alembic 管 schema

Milvus/Qdrant 适合亿级向量；本项目 ROI 不足。

## 3. DashScope / LLM 配置

配置集中在 `backend/app/core/config.py`：

| 环境变量 | 默认值 | 使用节点/服务 |
|----------|--------|---------------|
| `COACH_ROUTER_MODEL` | `qwen-plus` | `route_intent`、`safety_review` LLM |
| `COACH_PLANNER_MODEL` | `qwen-plus` | `plan_execute` |
| `COACH_ANSWER_MODEL` | `qwen-plus` | `sub_agent`、`synthesize`、`coach_chitchat`、摘要 |
| `COACH_EMBEDDING_MODEL` | `text-embedding-v3` | RAG、Graph 实体 linking |
| `EMBEDDING_DIM` | `1024` | 与 pgvector 列维度一致 |
| `COACH_LONG_CONTEXT_MODEL` | `qwen-long` | `LONG_CONTEXT_MODE=full` |
| `LLM_REQUEST_TIMEOUT_SECONDS` | `60` | httpx 超时 |
| `LLM_MAX_RETRIES` | `1` | 失败重试 |

`DashScopeClient`（`backend/app/llm/dashscope_client.py`）封装：

- `chat()` — 非流式，planner/router/safety
- `chat_stream()` — synthesize/chitchat 增量 SSE
- `chat_stream_with_tools()` — sub_agent ReAct 工具循环
- `embedding()` — 批量向量化

Base URL：`https://dashscope.aliyuncs.com/compatible-mode/v1`（OpenAI 兼容）。

## 10. 选型问答（Interview Cheat Sheet）

**为什么 PostgreSQL + pgvector 而不是专用向量库？**  
单库简化运维；chunk 量级在千～万级，pgvector 余弦检索足够；Graph 实体同库 JOIN 方便。

**为什么 LangGraph 而不是自写状态机？**  
`Send` 原生并行、`astream_events` 观测、`Annotated` reducer 合并子图输出；减少样板代码。

**为什么 DashScope？**  
中文运动健康语料表现好；OpenAI 兼容接口便于切换；embedding 与 chat 同一供应商。

## 常见追问

### Q1：`qwen-plus` 和 `qwen-long` 怎么分工？

**答**：默认全链路 `qwen-plus`；仅 `LONG_CONTEXT_MODE=full` 时 `MemoryService` 解析出 `coach_long_context_model` 供超长历史（当前 build 仍以窗口+摘要为主，full 模式保留全量 pair）。

**追问链**：
- *追问*：Planner 为何也用 plus？→ 规划 JSON 需稳定结构化输出，与 answer 同族降低 prompt 漂移。

### Q2：LangGraph 版本升级风险？

**答**：项目用 `astream_events(..., version="v2")` 与 `Send` API；升级需跑 `test_coach_graph.py`、`test_sse_bridge.py`。

### Q3：为何不用 LangChain AgentExecutor？

**答**：sub_agent 自实现 ReAct 循环（`chat_stream_with_tools`），更可控 SSE、token 记账与 `sub_agent_max_tool_steps`。

### Q4：pgvector 维度错了会怎样？

**答**：embedding API 返回 1024 维；与 `EMBEDDING_DIM`、DB 列不一致会在 insert/query 时报错。

### Q5：LoRA 在生产吗？

**答**：否。`LORA_ENABLED=false`；`scripts/finetune_lora.py` 为实验脚本，见 LLM_FINETUNE_EXPERIMENT。

### Q6：前端为何不用 TanStack Query？

**答**：会话与 SSE 状态耦合在 `useSessions`；体量小，Context + Hooks 足够。
