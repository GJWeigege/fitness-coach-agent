## 3. 路由系统详解

### 3.1 路由树结构

```text
/auth                    GuestRoute → AuthPage
/                        ProtectedRoute (需 token+me)
 └── MainLayout          Sidebar + Outlet
      ├── / → redirect /chat
      ├── /chat          ChatPage
      ├── /profile       ProfilePage
      ├── /knowledge     KnowledgeRoute (knowledge:read)
      ├── /agent-runs    AgentRunsRoute (observability:read)
      ├── /benchmark     BenchmarkRoute (benchmark:read|run)
      └── /users         UsersRoute (user:manage)
```

### 3.2 守卫组件

```22:61:frontend/src/router.tsx
function ProtectedRoute() {
  if (loading) return <LoadingScreen />;
  if (!token || !me) return <Navigate to="/auth" replace />;
  return <Outlet />;
}

function PermissionRoute({ allowed, children }) {
  if (!allowed) return <Navigate to="/chat" replace />;
  return children;
}
```

**加载竞态**：有 token 时 `loading=true` 直到 `fetchMe` 完成，避免闪烁跳转。

### 3.3 URL ↔ 权限 ↔ 菜单 三联表

| URL | 权限 | Sidebar |
|-----|------|---------|
| `/chat` | 登录 | Chat（全员） |
| `/profile` | 登录 | Profile |
| `/knowledge` | `knowledge:read` | Knowledge |
| `/agent-runs` | `observability:read` | Agent Runs |
| `/benchmark` | `benchmark:read` 或 `benchmark:run` | Benchmark |
| `/users` | `user:manage` | Users |

## 4. API 层架构

### 4.1 基座 client.ts

```1:47:frontend/src/api/client.ts
export const API_BASE = import.meta.env.VITE_API_BASE_URL || "http://localhost:8000";

export function buildHeaders(token?: string, extra?: HeadersInit): HeadersInit {
  return { ...(extra || {}), ...(token ? { Authorization: `Bearer ${token}` } : {}) };
}

export async function apiFetch<T>(url: string, init?: RequestInit): Promise<T> {
  const response = await fetch(url, init);
  if (!response.ok) throw new Error(await parseError(response, "Request failed"));
  return response.json();
}
```

**设计选择**：不引入 axios——SSE 需原生 `ReadableStream`，统一 fetch 减少依赖。

### 4.2 域模块职责

| 模块 | 主要函数 | 后端前缀 |
|------|----------|----------|
| `auth.ts` | `login`, `register`, `fetchMe`, `fetchUsers`, CRUD users | `/auth` |
| `chat.ts` | `fetchSessions`, `streamMessage`, `submitFeedback` | `/chat` |
| `profile.ts` | 画像、训练日志 | `/profile` |
| `knowledge.ts` | 文档列表、上传、reindex | `/knowledge` |
| `observability.ts` | `fetchAgentRuns`, `fetchAgentRunDetail` | `/observability` |
| `benchmark.ts` | `createBenchmarkRun`, `listBenchmarkRuns`, helpers | `/benchmark` |

### 4.3 barrel export

```1:7:frontend/src/api/index.ts
export * from "./auth";
export * from "./benchmark";
export * from "./chat";
...
```

`useSessions` 从 `"../api"` 导入——页面不关心具体文件，便于 mock。

### 4.4 非 JSON 响应

- `streamMessage`：自行解析 SSE

## 5. Hooks 详解

### 5.1 useSessions（核心）

**职责**：会话列表、当前会话、消息、流式发送、反馈、CRUD 会话。

**导出 API**：

```287:305:frontend/src/hooks/useSessions.ts
  return {
    sessions, activeSessionId, isDraftSession,
    setActiveSessionId: selectSession,
    messages, input, setInput, useRag, setUseRag, busy,
    loadSessions, loadSessionMessages, sendMessage,
    rateMessage, rename, remove, startNewSession,
  };
```

**副作用链**：

1. `token` 变化 → `loadSessions()`
2. `activeSessionId` 变化 → `loadSessionMessages()`
3. 首次有 sessions → 自动选第一条（`initialSessionPicked` ref 防重复）

**面试重点**：`sendMessage` 内 `handleEvent` 是 **纯函数式 reducer 风格**（`updateAssistant`），避免闭包陈旧 state 用 `setMessages(prev => ...)`。

### 5.2 useKnowledge

- 封装知识库文档列表、上传、删除、reindex
- 供 `KnowledgePage` 使用；与 Chat 解耦

### 5.3 useUsers

- admin 用户列表与 PATCH 更新
- 配合 `UsersPage` 角色下拉（数据来自 `permissionMatrix`）

### 5.4 useChatScroll

- 监听 `messages` 长度变化滚动到底部
- 纯 UI 副作用，不含业务

## 6. Context 边界

### 6.1 AuthContext

| 状态 | 存储位置 | 说明 |
|------|----------|------|
| `token` | localStorage + state | 持久登录 |
| `me` | memory | `/auth/me` 结果 |
| `permissions` | 派生 Set | `me.permissions` |
| `permissionMatrix` | memory | 角色→权限表，Users 页用 |

**不放 AuthContext 的**：Chat messages、sessions——避免全局刷新污染。

### 6.2 AppContext

仅 `error` / `setError` / `clearError`——跨页面 toast（Chat 流失败、API 错误）。

## 11. 常见追问

### Q1：为何不用 React Query？

**答**：会话与流式状态高度交互、乐观 UI 多；引入 Query 收益有限。面试可补充：列表类（knowledge runs）可用 Query 优化缓存，当前规模手动 fetch 足够。

**追问链**
- *追问*：重复请求如何防？  
  *答*：`busy` 锁发送；Benchmark `pollRef` 单定时器；sessions 仅在 token/activeSession 变化时拉取。

### Q2：LocalMessage 和 MessageItem 为何分开？

**答**：流式中间态（空 content、临时 id、steps）不应污染 API 类型；入库后 `loadSessionMessages` 回归 `MessageItem` 形状。

### Q3：权限变化后菜单何时更新？

**答**：login/logout/`fetchMe` 更新 `me.permissions` → `usePermissions` 重算 → Sidebar re-render。无 WebSocket 推送角色变更。

### Q4：Error toast 会覆盖吗？

**答**：单条 `AppContext.error`；新错误覆盖旧；用户手动关闭 `clearError`。

### Q5：如何做 E2E 测试？

**答**：仓库当前以 backend pytest 为主；前端可补 Playwright：登录三角色 → 断言 Sidebar 项 → mock stream。面试如实说「待完善」并给出方案。

### Q6：Markdown 渲染安全吗？

**答**：`MarkdownContent` 应限制 raw HTML（需结合实现）；用户内容是 assistant 输出经后端护栏，风险低于任意用户 HTML。

### Q7：为何 Router 用 createBrowserRouter 而非 Routes？

**答**：Data Router API 支持 `future flags`、嵌套 Outlet 更清晰；与 React 19 兼容。

### Q8：组件样式方案？

**答**：原生 CSS class（`app.css` 等），无 Tailwind——降低依赖，面试说「demo 够用，生产可换 CSS Modules」。
